# ADR — Registro de Decisiones Técnicas (2026-08-01)

Formato: estado (Aceptada/Rechazada/Supersedida), contexto, decisión,
consecuencia.

---

## ADR-001: Manifest apunta al modelo local real
- **Estado**: Aceptada
- **Contexto**: `nano.manifest.json` apuntaba a
  `C:\llama-cpp-server\models\...` (inexistente); el servidor lo
  sobreescribía con `--model data/qwen_tmp.gguf`.
- **Decisión**: Cambiar `local_model.path` a `data/qwen_tmp.gguf`.
- **Consecuencia**: CLI y servidor coherentes; verificado (10.97 tok/s con
  config default).

## ADR-002: Intervalo de inferencia del observatorio = 6s
- **Estado**: Aceptada
- **Contexto**: Ciclos más cortos queman 100% CPU en laptop.
- **Decisión**: `NANO_INFERENCE_INTERVAL_S=6` (configurable por env).
- **Consecuencia**: ~10 mediciones/min con carga moderada.

## ADR-003: Build CUDA para la RTX 3050 (sm_86)
- **Estado**: Aceptada
- **Contexto**: El build por defecto compilaba 7 arquitecturas CUDA
  (75–121a) → horas de compilación; y el feature `cuda` de nanortime-ffi
  era un placeholder vacío.
- **Decisión**:
  1. `vendor/llama-cpp-sys-2` parcheado: `CMAKE_CUDA_ARCHITECTURES` =
     `NANO_CUDA_ARCH` (default `86`) — 7× menos trabajo de compilación.
  2. `[patch.crates-io]` en el workspace apunta al vendor.
  3. `nanortime-ffi/build.rs` emite el LIBPATH de CUDA (find_cuda_helper
     fallaba).
  4. `llama-cpp-2` con feature `cuda`; `cuda = ["llama-cpp-2/cuda"]`.
- **Consecuencia**: 42.89 tok/s (vs 10-18 CPU), VRAM 1549 MB, GPU util 47%.
  Build completo ~25 min (vs horas).

## ADR-004: Suite de tests persistente
- **Estado**: Aceptada
- **Contexto**: Validación ad-hoc no reproducía.
- **Decisión**: `tests/` con 4 suites (server 12, sync 6, lógica 16,
  vivos 12 = 46 tests) + harnesses de benchmark PC/móvil.
- **Consecuencia**: Regresión automatizada en cada cambio.

## ADR-005: Servidor WS — fuente única de datos (broadcast)
- **Estado**: Aceptada (2026-08-01, encontrado por test de stress)
- **Contexto**: El handler WS generaba un snapshot por cliente con su propio
  step; `manager.broadcast` existía pero era código muerto. El test
  multi-cliente mostró streams con timestamps distintos entre clientes.
- **Decisión**: Un solo loop de telemetría → `broadcast` a todos; el
  handler solo gestiona conexión/desconexión.
- **Consecuencia**: 3 clientes reciben snapshots idénticos (15/15
  verificado). Elimina código muerto. Sin regresión (12/12 tests).

## ADR-006: Métricas del paper ancladas a evidencia
- **Estado**: Aceptada
- **Contexto**: El `check_completeness.py` validaba strings contra un DOCX
  externo con cifras infladas (2.90 tok/s = `Math.random()` de un HTML de
  demo; 26.7%, <1MB, +296/+351 MB sin respaldo de logs).
- **Decisión**:
  - Eliminar del paper toda métrica sin respaldo de log.
  - Anclar a artefactos reales (`android_benchmark_report.md`,
    `termux_setup.md`, `research_findings.md`).
  - Re-validar en vivo (sesión 2026-08-01): delta RSS 0.5 MB, 3.23/2.52
    tok/s móvil 1.5B, 0.14-0.38 tok/s 7B, RSS llama.cpp 2030-2501 MB.
- **Consecuencia**: Paper alineado a evidencia + Reproducibility Statement.

## ADR-007: Degradación bajo demanda de la inferencia del observatorio
- **Estado**: Aceptada
- **Contexto**: Correr inferencia sin clientes conectados quema CPU/GPU.
- **Decisión**: El loop de inferencia solo corre mientras hay conexiones WS
  activas.
- **Consecuencia**: 0% carga en vacío; medición solo cuando se observa.
